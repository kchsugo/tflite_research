# 두 갈래 통합 — 분할 + 라우팅 → 통합 플래너 (PPT용)

> 이전엔 따로 돌던 두 도구를 하나로 합쳤다.

---

## 1. 이전: 두 로직이 따로 있었다

| | 로직 A — 분할 (`jackson_online`) | 로직 B — 라우팅 (`online`) |
|---|---|---|
| 무엇 | task 1개를 CPU/GPU로 **쪼갬** (1컷) | 통짜 task를 GPU/CPU로 **배분** |
| 보는 단위 | task 1개씩 | 배치 전체 |
| CPU 사용 | 분할의 CPU-part | 통짜 task를 CPU 코어로 |
| 한계 | 통짜 최적이면 **CPU 놀림** | 분할 개념 없음 |

**핵심 문제**: 서로 다른 질문에 답 → 한쪽만 쓰면 반쪽짜리
- A만: "이 task 쪼갤까?" → 아니오 → **CPU 안 씀**
- B만: "노는 CPU에 통짜 줄까?" → 예 → **분할은 못 함**

---

## 2. 통합 아이디어

**두 결정을 하나의 목적함수로:**

```
각 task ∈ { 통짜-GPU,  통짜-CPU,  분할(k) }

makespan = max( GPU레인,  CPU레인(P코어) )  최소화
   GPU레인 = Σ 통짜-GPU + Σ 분할.gpu_stage
   CPU레인 = Σ 통짜-CPU + Σ 분할.cpu_stage  (P코어 분배)
```

→ 하나의 식이 A와 B를 **동시에** 수행:
- 분할이 이득 → 분할 (A)
- 통짜 최적이라도 GPU 병목 → 통짜 task를 CPU로 offload (B)

---

## 3. 통합 후 (`unified.cc`)

```
                  ┌─────────────────────────────┐
   배치 N개  →    │  통합 플래너 (3모드 배정)    │
                  │  makespan = max(GPU, CPU)    │
                  └──────────────┬──────────────┘
                     ┌───────────┼───────────┐
                 통짜-GPU     통짜-CPU       분할
                (메인 직렬)  (P코어 풀)   (jackson 방식)
```

- **통짜-GPU** = 로직 B의 GPU측 (모델당 공유 컨텍스트, 직렬)
- **통짜-CPU** = 로직 B의 CPU측 (P코어 병렬 분산)
- **분할** = 로직 A (jackson, 1컷) — 이득일 때만

---

## 4. 통합으로 얻은 것

1. **한 도구가 상황 따라 자동 선택** — 분할/통짜/CPU배분을 하드코딩 안 함
2. **"통짜 최적인데도 GPU 병목이면 CPU로 offload"** 가능 (A만으론 불가능했던 것)
3. **분할은 프레임에 유지** → 미래 int8/새 testset에서 이득이면 자동 적용
4. **캘리브레이션으로 배정 정확** → 과잉 offload 참사(0.56x) 제거

---

## 5. 한 줄 메시지

> **분할(A) + 라우팅(B) = 통합 플래너.** 두 개의 반쪽 최적을 하나의 목적함수로 합쳐,
> 어떤 배치가 와도 통짜·CPU·분할 중 최적을 자동 선택한다.
