# 통합 플래너 — 이전 대비 변경점 (PPT용)

> 환경: RTX 3060 Laptop(6GB, OpenCL) + i5-11400H(6C) / TFLite fp32

---

## 한 줄 요약

정적 비용표·강제 분할 → **실측 기반 통합 배정**으로 참사(0.56x) 제거 + 필요할 때만 CPU 활용.
분할은 프레임에 남겨 미래(int8) 대비.

---

## 1. Cut 선택 로직

| | 이전 | 변경 후 |
|---|---|---|
| 방식 | 균형점(cpu≈gpu) 이진탐색 | **전체 k 스윕** |
| 통짜(k=0) | 후보 아님 → **무조건 분할 강제** | **후보 포함** → 실제 cost 최소점 선택 |
| PCIe 경계 | 미반영 | gpu_stage에 이미 포함 (자동 반영) |

**결과: 5개 모델 전부 "통짜 GPU"가 최적임을 실측 증명** (`gpu_stage ≥ Gwhole` → 분할은 negative-sum)

---

## 2. 비용 모델

| | 이전 | 변경 후 |
|---|---|---|
| 값 | 정적 표 + **α=1.5 매직넘버** | **런타임 캘리브레이션** (실측 g_eff/c_eff) |

**발견**: CPU 6개 동시 실행 = **17.96ms** (정적 표는 9.56ms → 코어 경합 2배를 누락)

---

## 3. 통합 플래너 (신규 `unified.cc`)

| | 이전 | 변경 후 |
|---|---|---|
| 구조 | 분할(jackson) / 라우팅(online) **따로** | **한 도구로 통합** |
| 결정 | 각각 다른 로직 | **{통짜-GPU, 통짜-CPU, 분할} 한 목적함수** |
| 목적함수 | — | `makespan = max(GPU레인, CPU레인)` 최소화 |
| 코어 | GPU가 CPU에 굶김 | **GPU 구동 코어 1개 예약** |

→ "통짜 최적이라도 GPU 병목이면 CPU로 offload(B) + 분할 이득이면 분할(A)"을 동시 수행

---

## 4. 실측 결과 (mobilenet 배치)

| batch | 이전 (online) | 통합 플래너 | 배정 |
|---|---|---|---|
| ×10 | **0.56x** (6개 과잉 offload) | **1.05x** | GPU10 / CPU0 (offload 안 함) |
| ×30 | — | **1.12x** ✅ | GPU25 / CPU5 (CPU 활용, 이득) |
| ×50 | — | **1.01x** | GPU40 / CPU10 (손해 소멸) |

- **참사(0.56x) 제거**: 캘리브레이션이 실제 경합을 잡아 과잉 offload 방지
- **×30에서 1.12x**: GPU 큐 > CPU 1개 → CPU가 GPU와 병렬 → 시간·사용량 둘 다 이득
- **전부 ≥ 1.0x**: 예전 손해 구간 소멸

---

## 5. 핵심 메시지

1. **강제 분할 → 통짜 포함 최적 선택** (분할은 이 HW에서 negative-sum임을 증명)
2. **매직넘버 → 실측 캘리브레이션** (경합·연속실행 반영)
3. **분리된 두 로직 → 하나의 통합 플래너** (통짜·CPU라우팅·분할 통합)
4. **분할은 프레임에 유지** → 미래 int8/새 testset에서 이득이면 자동 적용
